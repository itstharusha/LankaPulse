2. DATA SOURCES
======================================================================
A) Exchange rates (CBSL via Frankfurter API)
   - Free, no API key. CBSL indicative rates, 56 currencies, 2011 to present.
   - Latest:      https://api.frankfurter.dev/v2/rates?providers=CBSL
   - Historical:  https://api.frankfurter.dev/v2/rates?from=YYYY-MM-DD&providers=CBSL
     (the docs show a "group=month" option; check the docs page https://frankfurter.dev/providers/cbsl/ for daily date-range parameters before you build)
   - Official source for reference: https://www.cbsl.gov.lk/en/rates-and-indicators/exchange-rates

B) Tourist arrivals (SLTDA monthly reports, PDF)
   - Monthly Tourist Arrivals Reports published by Sri Lanka Tourism Development Authority.
   - Files live under https://www.sltda.gov.lk/storage/common_media/ with inconsistent names, for example:
       MonthlyTouritsArrivalsReport-May-2026-Final-1.pdf
       Monthly_Tourits_Arrivals_Report-October-2025-Final.pdf
       MonthlyTouritsArrivalsReport-June-2026-Final-Updated_1.pdf
   - Some months have "Updated" re-issues. You must keep the latest version only.
   - Contents include monthly totals, arrivals by region, and arrivals by country of residence.
   - Because names are inconsistent, build a manifest table (month, url, version, status) by hand or by scraping the SLTDA reports page, then drive the pipeline from the manifest.

C) Weather (Open-Meteo Historical Weather API)
   - Free for non-commercial use, no API key, data back to 1940, licensed CC BY 4.0.
   - Endpoint: https://archive-api.open-meteo.com/v1/archive
   - Parameters: latitude, longitude, start_date, end_date, daily (for example temperature_2m_max, temperature_2m_min, precipitation_sum, wind_speed_10m_max), timezone=Asia/Colombo
   - You must display a link such as "Weather data by Open-Meteo.com" in your README and report.
   - Suggested locations (name, lat, lon):
       Colombo 6.9271, 79.8612
       Kandy 7.2906, 80.6337
       Galle 6.0535, 80.2210
       Nuwara Eliya 6.9497, 80.7891
       Sigiriya 7.9570, 80.7603
       Arugam Bay 6.8400, 81.8350

D) Not used: Colombo Stock Exchange prices
   - Historical CSE data is sold by the exchange. Free options are third-party scrapers. Skip it.
   - Optional extra later: CBSL statistical tables (monthly Excel) if you want a macro dimension. Verify availability and terms first.

3. ARCHITECTURE
======================================================================
Sources                       Orchestration            Storage / Processing                 Serving
-------                       -------------            --------------------                 -------
Frankfurter API (FX)   --\
Open-Meteo API (weather) --+-> ADF pipelines  ->  ADLS Gen2: raw -> cleansed -> curated -> Azure SQL star schema -> Power BI
SLTDA PDFs (arrivals)  --/        |                     |  (Parquet)     (Parquet)              ^
                                  |                     +-> quarantine (rejected rows)          |
                                  +-> Azure Functions (Python transforms + DQ checks) -----------+
                                  +-> Azure Monitor alerts on failure
                                  +-> pipeline_run_log and dq_results tables in Azure SQL

Layers:
- raw: untouched copies of source data, partitioned by ingest date. Never edited.
- cleansed: typed, deduplicated, standardized Parquet. Rows failing checks go to quarantine.
- curated: business-ready Parquet and SQL tables modelled as a star schema.

7. ADF PIPELINES
======================================================================
Use parameters everywhere. No hard-coded dates, URLs, or paths.

PIPELINE 1: pl_ingest_fx_daily
- Trigger: daily, after Sri Lanka business hours.
- Steps:
  1. Lookup activity: read last loaded date from pipeline_watermark table (dataset = fx).
  2. Copy activity (REST source, ADLS JSON sink): pull rates from watermark+1 to today.
  3. Azure Function activity: transform_fx (raw JSON to cleansed Parquet, with DQ checks).
  4. Stored procedure activity: load curated fact_fx_rate_daily (incremental, MERGE).
  5. Stored procedure activity: update watermark.
  6. Log success or failure to pipeline_run_log (use on-failure path).
- First run: backfill from 2011-01-01 in yearly chunks using a ForEach over a list of year ranges.

PIPELINE 2: pl_ingest_weather_daily
- Trigger: daily.
- Parameters: list of locations (name, lat, lon).
- Steps: ForEach location -> Copy (REST) -> Azure Function transform_weather -> stored procedure load -> watermark update per location.
- First run: backfill from 2015-01-01 (or 2011 to match FX), in yearly chunks per location.
- Note: archive data lags the present by a few days. Set end_date = today minus 5 days and test.

PIPELINE 3: pl_ingest_sltda_monthly
- Trigger: monthly (SLTDA publishes after month end, often with a delay) plus manual rerun.
- Steps:
  1. Lookup: read manifest rows where status = 'pending' or version updated.
  2. ForEach manifest row: Copy activity (HTTP binary source, ADLS sink) into raw/sltda/.
  3. Azure Function ingest_sltda_pdf: parse tables, write cleansed/arrivals Parquet, run reconciliation checks, update manifest status (loaded / failed / needs_review).
  4. Stored procedure: load fact_tourist_arrivals_monthly (MERGE; if a month is re-issued as "Updated", replace that month).
  5. Log to pipeline_run_log.

PIPELINE 4: pl_master_orchestrator
- Runs the three pipelines in order (arrivals depend on dim_country being current), then refreshes marts and runs the final DQ summary.
- Single place to alert on failure.

Triggers: schedule triggers for 1, 2, 3 or the master only. Tumbling window trigger is optional for the backfill.

Alerting: create an Azure Monitor alert rule on "Pipeline run failed" for the factory, with an email action group.

8. PYTHON TRANSFORMS (Azure Functions)
======================================================================
General rules:
- Use pandas + pyarrow. Read from and write to ADLS with azure-storage-file-datalake and azure-identity (managed identity if possible).
- Every function takes run_id, dataset, and source/target paths as input and returns row counts (read, written, rejected) as JSON for ADF to log.
- Never overwrite raw. Write deterministic outputs so reruns are idempotent.

transform_fx:
- Parse JSON to columns: rate_date, base_currency (LKR), quote_currency, rate, provider (CBSL), ingest_ts.
- Check: rate > 0, valid ISO currency code, no duplicate (rate_date, currency).
- Note the direction of the rate (LKR per 1 unit of foreign currency vs the inverse). Document it in the data dictionary and standardize.

transform_weather:
- Columns: observation_date, location_key, temp_max_c, temp_min_c, precip_mm, wind_max_kmh.
- Check: precip >= 0, temp_min <= temp_max, temperatures in a plausible range for Sri Lanka, no missing dates per location, no duplicates.

ingest_sltda_pdf (the hardest part, and your best story):
- Use pdfplumber (or camelot) to extract the "arrivals by country of residence" table and the monthly totals table.
- Standardize country names via a mapping file (for example "Russian Federation" vs "Russia"). Keep unmapped names in a review list instead of guessing.
- Output columns: report_month, country_name, region, arrivals, pct_share, report_version, source_file.
- Layout changes between months. Build the parser defensively, add a parser test per layout you see, and on failure set manifest status = needs_review instead of loading bad data.
- Reconciliation: sum of country arrivals vs the total stated in the report. Allow a tiny tolerance only if justified, and log the difference.

9. CURATED SCHEMA (Azure SQL, T-SQL)
======================================================================
Schemas: stg, dw, ops

-- Dimensions
CREATE TABLE dw.dim_date (
  date_key INT PRIMARY KEY,            -- YYYYMMDD
  full_date DATE NOT NULL,
  year SMALLINT, quarter TINYINT, month TINYINT, month_name VARCHAR(12),
  week_of_year TINYINT, day_of_week TINYINT, is_weekend BIT,
  is_business_day BIT, season VARCHAR(20)   -- optional: monsoon/season tag
);

CREATE TABLE dw.dim_country (
  country_key INT IDENTITY PRIMARY KEY,
  country_name VARCHAR(100) NOT NULL,
  region VARCHAR(50),
  iso_code CHAR(2) NULL,
  valid_from DATE, valid_to DATE, is_current BIT   -- SCD2 if names or regions change
);

CREATE TABLE dw.dim_currency (
  currency_key INT IDENTITY PRIMARY KEY,
  currency_code CHAR(3) NOT NULL UNIQUE,
  currency_name VARCHAR(60)
);

CREATE TABLE dw.dim_location (
  location_key INT IDENTITY PRIMARY KEY,
  location_name VARCHAR(60) NOT NULL,
  latitude DECIMAL(9,6), longitude DECIMAL(9,6),
  tourism_zone VARCHAR(40)
);

-- Facts
CREATE TABLE dw.fact_fx_rate_daily (
  date_key INT NOT NULL, currency_key INT NOT NULL,
  rate_lkr DECIMAL(18,6) NOT NULL,
  source_run_id VARCHAR(40),
  PRIMARY KEY (date_key, currency_key)
);

CREATE TABLE dw.fact_weather_daily (
  date_key INT NOT NULL, location_key INT NOT NULL,
  temp_max_c DECIMAL(5,2), temp_min_c DECIMAL(5,2),
  precip_mm DECIMAL(7,2), wind_max_kmh DECIMAL(6,2),
  source_run_id VARCHAR(40),
  PRIMARY KEY (date_key, location_key)
);

CREATE TABLE dw.fact_tourist_arrivals_monthly (
  month_date_key INT NOT NULL,         -- first day of month as YYYYMMDD
  country_key INT NOT NULL,
  arrivals INT NOT NULL,
  pct_share DECIMAL(6,3),
  report_version VARCHAR(30),
  source_run_id VARCHAR(40),
  PRIMARY KEY (month_date_key, country_key)
);

-- Ops tables
CREATE TABLE ops.pipeline_watermark (
  dataset VARCHAR(60) PRIMARY KEY, last_loaded_date DATE, updated_ts DATETIME2
);

CREATE TABLE ops.pipeline_run_log (
  run_id VARCHAR(40), pipeline_name VARCHAR(100), dataset VARCHAR(60),
  start_ts DATETIME2, end_ts DATETIME2, status VARCHAR(20),
  rows_read INT, rows_written INT, rows_rejected INT, error_message NVARCHAR(2000)
);

CREATE TABLE ops.dq_results (
  run_id VARCHAR(40), dataset VARCHAR(60), rule_id VARCHAR(40),
  rule_description VARCHAR(300), severity VARCHAR(10),   -- ERROR / WARN
  rows_checked INT, rows_failed INT, passed BIT, checked_ts DATETIME2
);

CREATE TABLE ops.sltda_manifest (
  report_month DATE, url VARCHAR(500), file_name VARCHAR(200),
  version_label VARCHAR(40), status VARCHAR(20),   -- pending/loaded/failed/needs_review
  last_checked_ts DATETIME2
);

Loading pattern: land in stg.* via Copy or Function, then MERGE into dw.* in stored procedures (insert new, update changed, never duplicate keys). Make every load rerunnable.

10. DATA QUALITY RULES (write these into docs/dq_rules.md)
======================================================================
Severity ERROR = reject rows to quarantine and fail the dataset load. WARN = load but log and alert.

FX
- FX01 (ERROR) rate is positive and not null
- FX02 (ERROR) no duplicate (date, currency)
- FX03 (WARN) a business day has no rate for a currency that had one the previous business day
- FX04 (WARN) day-over-day change above a threshold (for example 5 percent), flag for review

Weather
- WX01 (ERROR) no duplicate (date, location)
- WX02 (ERROR) temp_min <= temp_max
- WX03 (ERROR) precip_mm >= 0
- WX04 (WARN) missing dates in the loaded range for a location
- WX05 (WARN) value outside plausible range

Arrivals
- AR01 (ERROR) arrivals is a non-negative integer
- AR02 (ERROR) no duplicate (month, country)
- AR03 (ERROR) sum of countries reconciles to the report total (log the difference)
- AR04 (WARN) country name not in mapping file
- AR05 (WARN) month-over-month or year-over-year change beyond a threshold
- AR06 (ERROR) one report version per month in the curated table

Cross-layer
- XL01 (ERROR) row counts: raw read = cleansed written + quarantined
- XL02 (WARN) freshness: latest FX and weather date within an expected lag

Every check writes a row to ops.dq_results. Every rejected row carries a reject_reason in quarantine.
